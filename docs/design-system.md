# SlydeCode Design System

> Status: **implemented baseline** (editor, presenter and copilot ship these tokens). Changes still require a design pass before implementation.
> Scope: the application shell (editor + presenter + copilot). Slide content generated by the AI inherits the same tokens through a restricted, documented subset.

---

## 1. Position

SlydeCode is a studio, not an IDE. The interface has to feel like a design tool a teacher can open on day one, while the thing underneath is a compiler. Every decision below follows from one rule: **the code is the medium, never the message.**

Two consequences that shape the whole system:

- No terminal aesthetics. No monospace outside Developer Mode. No brackets, no `</>`, no green-on-black.
- The AI is a visible collaborator with human language. It says *"Writing slide 3…"*, never *"streaming JSON-RPC"*.

### 2.3 The signature gradient

`--gradient-signature: linear-gradient(135deg in oklch, #7C3AED 0%, #FF6B4A 100%)`

- Interpolating **in OKLCH** keeps the midpoint luminous instead of the muddy magenta you get in sRGB. Fallback for older engines: plain `linear-gradient(135deg, #7C3AED, #FF6B4A)`.
- **Where it is allowed:** logo, AI status chip, generation sweep, 1px focus/selection rings, progress fills, presenter's "AI generated" seal, and display-size type (≥24px).
- **Where it is not:** small text, body copy, icons under 16px, or as a background behind white body text. `#FF6B4A` on white is ~2.8:1 — it fails even the 3:1 graphics threshold.

**Action variant for text safety.** Primary buttons do not use the full gradient, because white text over the coral end would fail AA. They use `--gradient-action: linear-gradient(135deg, #6D28D9, #7C3AED)` with white text (≥5.7:1), and the coral appears only in the hover ring/glow. This is a deliberate accessibility decision, not an omission.

## 3. Typography

**Geist Sans** for everything in the UI (fallback: Inter, system-ui). **Geist Mono** only inside Developer Mode and code views (fallback: JetBrains Mono, ui-monospace).

Both families ship **bundled** as variable woff2 files in `assets/fonts/` (Geist 1.8.2, SIL OFL 1.1 — see `assets/fonts/README.md`) and are served at `/fonts` on the app origin and on the sandbox origin. `font-display: swap`; the UI preloads the upright sans face. Slides use the same files, so exports do not depend on the machine's installed fonts.

| Token | Size / line-height / tracking | Use |
|---|---|---|
| `display` | 56 / 1.02 / -0.03em | Empty states, presenter titles |
| `h1` | 32 / 1.15 / -0.02em | Project title, modal titles |
| `h2` | 22 / 1.25 / -0.015em | Panel sections |
| `h3` | 17 / 1.35 / -0.01em | Card titles, slide names |
| `body` | 15 / 1.55 / 0 | Default text |
| `ui` | 13.5 / 1.45 / 0 | Dense controls, inspector rows |
| `label` | 12.5 / 1.3 / 0.01em, medium | Field labels (sentence case, never ALL CAPS) |
| `micro` | 11 / 1.4 / 0.02em | Slide numbers, timers |
| `mono` | 12.5 / 1.6 / 0 | Dev Mode only |

Rules:

- Base 15px for UI density; never below 12px for anything a user must read.
- Sentence case everywhere. No all-caps labels, no eyebrow labels.
- `font-variant-numeric: tabular-nums` for the timer, slide counter and any aligned numbers.
- Line length in prose ≤ 72ch; in panels, wrap naturally, never justify.
- Weight palette: 400 / 500 / 600. No 700+ in the UI (it shouts); 700 only in slide content if the template asks.

## 4. Space, radius, elevation

**Space scale (4px base):** 2, 4, 6, 8, 10, 12, 16, 20, 24, 32, 40, 56, 72.

- Panel padding 16–20. Gap between controls 8. Section gap 24. Canvas gutter 32.
- Never mix 6/10/14 spacing in one cluster; pick from the scale.

**Radius:** 6 (chips), 10 (buttons, inputs), 14 (cards, thumbnails), 20 (modals, overlays), 999 (pills).

**Elevation (warm-tinted in light mode):**

| Token | Light | Dark |
|---|---|---|
| `--shadow-1` | `0 1px 2px rgba(28,22,18,.06)` | `0 1px 2px rgba(0,0,0,.5)` |
| `--shadow-2` | `0 4px 14px -4px rgba(28,22,18,.10), 0 2px 4px -2px rgba(28,22,18,.06)` | `0 6px 18px -6px rgba(0,0,0,.65)` |
| `--shadow-3` | `0 18px 48px -16px rgba(28,22,18,.18)` | `0 24px 60px -20px rgba(0,0,0,.75)` |
| `--glow-brand` | `0 10px 30px -10px rgba(124,58,237,.40)` | `0 10px 34px -10px rgba(155,107,255,.45)` |

Elevation communicates layering only. No shadow on flat panels; the app is not a stack of cards.

## 5. Layout

```
┌──────────────────────────────────────────────────────────────┐
│ Top bar 56px: logo · project name · theme gallery · AI chip · actions │
├──────────┬──────────────────────────────────────┬────────────┤
│ Storyboard│              Stage                   │ Inspector  │
│  232px    │        centered 16:9 canvas          │  352px     │
│ collapsible│      on surface-sunken backdrop      │ Inspector/Copilot tabs │
├──────────┴──────────────────────────────────────┴────────────┤
│ HUD 36px: slide n/total · connection dot · zoom              │
└──────────────────────────────────────────────────────────────┘
```

- Minimum window 1024×680. Below 1100px the right panel is hidden; below 1024 the storyboard collapses to a filmstrip rail of 96px. The copilot is a desktop-panel surface for now.
- The canvas is always letterboxed, never stretched: the aspect ratio is a property of the deck, not of the window.
- Panel widths are fixed; the stage absorbs all remaining space. No fluid three-column math.
- Alignment: everything left-aligned except slide content (per template) and centered empty states.

## 6. Motion

| Token | Value |
|---|---|
| `--dur-1` | 120ms (state feedback: hover, press) |
| `--dur-2` | 180ms (chips, tooltips, small reveals) |
| `--dur-3` | 260ms (panels, drawers) |
| `--dur-4` | 420ms (slide transitions) |
| `--dur-5` | 700ms (generation sweep, once) |
| `--ease-out` | `cubic-bezier(.16,1,.3,1)` |
| `--ease-in-out` | `cubic-bezier(.65,0,.35,1)` |
| `--ease-spring` | `cubic-bezier(.34,1.56,.64,1)` — thumbnails settling only |

Rules:

- Animate `transform` and `opacity` only. Never `width`, `height`, `top`, `left`, or `box-shadow` in a loop.
- Exits run at 0.7× the entrance duration. Nothing lingers.
- One orchestrated moment per action. No ambient loops except the AI chip's 2.4s shimmer while a generation is in flight.
- `prefers-reduced-motion: reduce` → opacity fades only, sweep replaced by a single 120ms tint, particles removed, spring removed.
- Never a spinner for generation. Progress is always a spatial, content-anchored signal.
- Copilot motion is quiet: the provider sheet enters with a 220ms opacity +
  4px translate, tool rows settle in 180ms, and the only loop is the 2px
  streaming caret and the tab's 6px live dot. Reduced motion removes the
  translate and the caret blink, leaving a static caret for the duration of
  the stream.

### 6.1 The generation sequence (the signature moment)

1. **0ms** — AI chip enters `Writing slide 3…` (180ms, no bounce).
2. **0ms** — Canvas dims 4%; a warm scan band (16% tall, led by a bright coral edge) sweeps top→bottom once (700ms).
3. **As elements land** — each block fades in and scales 0.985→1 with a 40ms stagger, in DOM order.
4. **While active** — exactly one micro-label is visible, anchored to the element being written (`Adjusting layout…`, 12.5px, `--ink-muted`). Never two.
5. **End** — chip settles to `Done` with a 120ms check draw; the sweep exits upward; the done label holds for 2.6s and fades out at 180ms.

No JSON, no logs, no percentages. The user sees the slide being composed.

**Implementation note — inferred activity (current).** External MCP agents do not stream tokens, so the studio infers activity from the structured `agent_activity` WebSocket events the server emits around `/api/agent`. The active phase is held for at least 1s before `Done`; the done confirmation then holds for 2.6s. There is deliberately **no synthetic “still working” tail** after a concluded call, because the agent is finished and the label would be false. The sweep runs only for `upsert_slide` when the target slide is the selected one. `Done` auto-follows the written slide only if the user has been idle for 1.8s and focus is not inside a form control or the storyboard. The `thinking` state belongs to the copilot: its explicit streaming channel emits it on request start and between tool rounds, while its mutations emit the same writing/done events as MCP. External agents never emit `thinking` because they do not stream tokens. The copilot panel also carries a local tab dot and thread caret, so the panel is legible without looking at the stage chip.

## 7. Logo & isotipo

- **Isotipo:** a 24×24 rounded square (radius 6) outlining a slide, with a 2px vertical caret bar inside, filled with the signature gradient. It reads as *a cursor writing a slide* — no brackets, no terminal.
- At 16px the caret thickens to 2.5px and the square radius drops to 5px so it stays legible.
- **Wordmark:** "SlydeCode", Geist Semibold, tracking -0.02em. `Slyde` in `--ink`, `Code` in `--brand`. The gradient on "Code" is allowed only at ≥20px.
- Clear space: 0.5× the cap height on all sides. Minimum sizes: 16px isotipo, 96px wordmark.
- Never: `</>` or angle brackets, terminal green, rainbow gradients, the gradient rotated or with more than two stops.

## 8. Components & states

- **Button:** primary (`--gradient-action`, white text, 36px tall, radius 10), secondary (surface + border), ghost (transparent, ink-muted), destructive. Icon buttons 32×32 with `aria-label` and tooltip.
- **AI status chip:** pill, 28px tall, gradient ring at 1.5px, dot + label. States: idle, thinking, writing, adjusting, animating, done, error. A separate `role="status"` live region announces visual phase changes; the chip itself is non-interactive in the inferred-activity layer, and replaying the last generation is a later affordance.
- **Thumbnail:** 16:9, radius 14, 1px border, live render (not a screenshot), selected state = 2px `--brand` ring + 2px offset. Drag handle appears on hover only.
- **Inspector row:** label left (12.5px, muted), control right, 32px tall, hairline between groups. Controls mutate the generated code underneath; the UI never asks the user to type CSS.
- **Empty state:** one line of what to do next, one primary action. No illustrations of sad robots.
- **Error:** states what failed and the next action ("Couldn't render slide 3. Retry"). No apology, no stack trace outside Dev Mode.
- **Skeleton:** slide-shaped, `--surface-sunken`, 1.2s shimmer, `aria-busy` on the container, space reserved so nothing jumps.
- **Connection:** 6px dot (success/warning/danger) with a human tooltip ("Connected"), never a protocol name.

### 8.1 Copilot panel

The right panel is a two-tab surface: **Inspector** and **Copilot**. Tabs use
`role="tablist"`, roving `tabindex`, a 2px `--brand` underline for the selected
tab, and a 6px live dot while a response streams. The panel is 352px wide so the
conversation has room for code-free prose and attachment chips without wrapping
every line.

- **Provider header:** one full-width trigger (icon, provider name, selected
  model / "Choose a model") plus a 32px new-chat icon. It opens the provider
  sheet; it never renders a saved key.
- **Thread:** user messages sit in a soft `--surface-sunken` card, assistant
  messages run edge-to-edge with a 24px sparkle avatar. A token-by-token stream
  ends in a 2px blinking caret. The thread is `aria-live="off"` because
  announcing every token is hostile; one polite announcer reports completion.
- **Tool rows:** hairline rows with a small spinner/check/error glyph and a
  localized phase label ("Writing the slide…"). Tool names come from the model;
  the UI maps them to its own strings and never renders model free text.
- **Composer:** one bordered card that lifts to a brand focus ring. Textarea
  autosizes (24–152px), `Enter` sends, `Shift+Enter` breaks. Actions: attach,
  model chip, 32px send/stop. A 9.5px footnote states that the copilot edits the
  real deck.
- **Attachments:** chips with file name + size, a 32px remove target and a
  localized error for unsupported/oversized files. Limits: 4 per message, 5 MB
  images, 12 MB documents.
- **Provider sheet:** an in-panel modal (`role="dialog"`) that covers the panel,
  not the stage. 4×2 provider grid with brand marks, a key form with show/hide,
  then a searchable model list with a **Free** toggle, context badges and a
  selected check. `Esc` closes and restores focus to the provider trigger.
- **States:** loading (sparkle + "Loading…"), connect (one key action), error
  with retry, streaming, stopped, done and per-message retry. No raw provider
  errors, status codes or stack traces ever enter this surface.

### Developer Mode (opt-in, off by default)

Reveals: MCP log, state tree, raw JSON, FPS/RAM, and the code tab. Monospace, muted, dense. It is the only place where technical vocabulary is allowed.

## 9. Accessibility baseline

- Text ≥4.5:1; large text and graphics ≥3:1. Every text token pair is measured in both modes (`tests/ui/studio.test.mjs` fails below 4.5:1). Current worst pair: `--ink-subtle` on `--surface-sunken`, 4.7:1 in light mode.
- Visible focus ring: 2px `--brand` + 2px offset, never `outline: none` without a replacement. Inputs keep the ring as well as their border change.
- Keyboard: every action reachable; `Esc` closes overlays; arrow keys navigate the storyboard. Only the selected thumbnail is in the tab order, and focus follows the selection.
- Hit targets ≥32px for top-bar controls in the desktop shell (compact chips are ≥28px).
- All icon-only buttons have `aria-label`; status text is `aria-live="polite"`; the presenter exposes its progress as a `progressbar`.
- The copilot thread is `aria-live="off"` (token announcements are hostile); a
  dedicated polite announcer reports "Copilot finished responding" and localized
  errors. The provider sheet traps Tab/Shift+Tab, closes on `Esc` and returns
  focus to its trigger. The provider and model lists are keyboard-operable
  buttons, not hover-only cards.
- Slide content is rendered in a sandboxed iframe; the app's own chrome never inherits slide CSS.

## 10. i18n notes

- EN and ES ship together. Spanish runs ~15–20% longer: buttons use `min-width` + padding, never fixed widths; chips truncate with tooltip.
- No string concatenation for sentences with variables; use full message templates (`Writing slide {n}…`).
- Numbers, dates and the timer follow the locale (`Intl`), not hardcoded formats.
- Provider and model names are product nouns: never translate "ChatGPT",
  "Claude", "Gemini", "Grok", "Groq", "OpenRouter", "DeepSeek" or "NVIDIA".
- Copilot errors are localized from stable server codes (`missing_key`,
  `invalid_key`, `rate_limited`, `network`, `upstream`, `unsupported`,
  `invalid_request`); provider text is never displayed and never string-matched
  in the UI.
